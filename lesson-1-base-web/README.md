# Урок 1. Статика и веб

Поднимаем свой сайт, смотрим, где он живёт, на каком порту торчит и что отвечает.
Разбираем HTML/CSS/JS ровно настолько, чтобы понимать, из чего состоит страница
и откуда берутся файлы. Разговариваем с сервером через `curl`.

Сайт в уроке — упрощённая копия реального: [enjoyconnection.ru](https://enjoyconnection.ru).

---

## 0. Установка

Всё через **Chocolatey** — пакетный менеджер для Windows (аналог `apt` в Linux).

**Chocolatey.** PowerShell **от администратора**:

```powershell
Set-ExecutionPolicy Bypass -Scope Process -Force; `
[System.Net.ServicePointManager]::SecurityProtocol = [System.Net.ServicePointManager]::SecurityProtocol -bor 3072; `
iex ((New-Object System.Net.WebClient).DownloadString('https://community.chocolatey.org/install.ps1'))
```

Закрыть терминал, открыть заново, проверить:

```powershell
choco --version
```

**Hugo** (тот же PowerShell от администратора):

```powershell
choco install hugo-extended -y
hugo version
```

Должно быть `+extended` в конце строки версии.

> Альтернативы, если choco не хочется: `winget install Hugo.Hugo.Extended` или `scoop install hugo-extended`.

Ещё понадобится **Git Bash** (в нём есть `curl` и привычный shell):
`choco install git -y`

## 1. Запуск

Из папки урока:

```bash
hugo server
```

В выводе будет строка:

```
Web Server is available at http://localhost:1313/ (bind address 127.0.0.1)
```

Открой её в браузере. Остановить — `Ctrl+C`.

Полезные ключи:

```bash
hugo server --port 8080          # другой порт
hugo server --bind 0.0.0.0       # пустить в сеть (см. пункт 2)
hugo server --disableFastRender  # полная пересборка на каждое изменение
hugo                             # не запускать, а просто собрать сайт в папку public/
```

## 2. Что такое «поднять приложение»

Приложение — это **процесс**, который запустился и **слушает порт**. Всё.

- **Порт** — номер от 1 до 65535. Одна машина, много приложений — порт говорит,
  кому именно предназначен пакет. 80 — http, 443 — https, 1313 — hugo, 5432 — postgres.
- **Порт занят только одним процессом.** Запустишь два hugo на 1313 — второй упадёт с
  `bind: Only one usage of each socket address...`. Лечится `--port 8081` или убийством первого.
- **Адрес привязки (bind).** `127.0.0.1` = принимаю только с этой же машины.
  `0.0.0.0` = слушаю на всех сетевых интерфейсах, можно зайти с телефона.
  Это причина №1 для «у меня локально работает, а снаружи нет».
- **`localhost` / `127.0.0.1`** — петля (loopback), сам себе компьютер. Пакет не выходит в сеть.

Кто занял порт:

```bash
netstat -ano | grep 1313      # LISTENING + PID в последней колонке
tasklist | grep <PID>         # что это за процесс
taskkill //PID <PID> //F      # убить (в Git Bash двойной слэш)
```

`ping` — проверяет **только доступность машины**, про порты и HTTP не знает ничего:

```bash
ping 127.0.0.1
ping -4 localhost             # -4 обязательно: без него localhost может уйти в IPv6 (::1) и упасть
```

Ping проходит, а сайт не открывается — нормальная ситуация: машина жива,
приложение не запущено или слушает другой порт.

## 3. Где что лежит

```
lesson-1-base-web/
├── hugo.toml          конфиг: порт, заголовки ответа, редирект
├── content/           тексты страниц (markdown)
├── data/              тексты меню и главной (yaml) — отделены от вёрстки
├── layouts/           HTML-шаблоны
│   ├── baseof.html      общий каркас: head + шапка + контент + подвал
│   ├── home.html        главная
│   ├── page.html        обычная страница
│   ├── 404.html         страница «не найдено»
│   └── _partials/       переиспользуемые куски: head, navbar, footer
├── static/            отдаётся КАК ЕСТЬ, становится корнем сайта
│   ├── css/style.css   → http://localhost:1313/css/style.css
│   ├── js/app.js       → http://localhost:1313/js/app.js
│   └── images/logo.svg → http://localhost:1313/images/logo.svg
└── public/            результат сборки, появляется после запуска (в git не хранится)
```

Запусти `hugo` и загляни в `public/` — там **обычные .html файлы**. Никакого
приложения, никакой базы. Сервер просто отдаёт файлы с диска — это и называется
**статика**. Динамика — когда сервер собирает ответ на лету (Python, PHP, Node).

## 4. HTTP: запрос и ответ

Текстовый протокол. Клиент шлёт запрос, сервер шлёт ответ. Никакой магии.

**Запрос:** метод + путь + версия, потом заголовки.

```
GET /about/ HTTP/1.1
Host: localhost:1313
User-Agent: curl/8.2.1
Accept: */*
```

Методы: `GET` забрать, `POST` отправить, `PUT` заменить, `DELETE` удалить, `HEAD` только заголовки.

**Ответ:** код + заголовки + пустая строка + тело.

```
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 5128
Last-Modified: Wed, 05 Aug 2026 15:22:37 GMT
X-Lesson: lesson-1-base-web
```

Заголовки, которые надо знать:

| Заголовок | Смысл |
|---|---|
| `Content-Type` | что это: `text/html`, `text/css`, `image/svg+xml`. По нему браузер решает, рисовать или скачивать |
| `Content-Length` | размер тела в байтах |
| `Last-Modified` | когда файл менялся — основа кэша |
| `Location` | куда идти, приходит вместе с 3xx |
| `Cache-Control` | сколько держать в кэше |
| `X-*` | чьи угодно самописные, у нас `X-Lesson` из `hugo.toml` |

**Коды ответов:**

- `2xx` успех — 200 OK, 201 Created, 204 No Content
- `3xx` иди в другое место — 301 навсегда, 302 временно, 304 не менялось
- `4xx` виноват **клиент** — 400 кривой запрос, 401 не представился, 403 нельзя, 404 нет такого, 429 слишком часто
- `5xx` виноват **сервер** — 500 упал, 502 плохой ответ от бэкенда, 503 не тянет, 504 бэкенд молчит

Правило первой минуты: `4xx` — чинить запрос/права/адрес, `5xx` — идти в логи сервера.

## 5. curl — браузер без картинок

```bash
curl http://localhost:1313/                  # тело ответа (голый HTML)
curl -s http://localhost:1313/ | head -20    # -s убрать прогресс-бар
curl -I http://localhost:1313/               # ТОЛЬКО заголовки (метод HEAD)
curl -i http://localhost:1313/               # заголовки + тело
curl -v http://localhost:1313/               # весь диалог: > отправили, < получили
curl -o page.html http://localhost:1313/     # сохранить в файл
curl -L http://localhost:1313/old-page       # идти по редиректам
curl -H 'X-My: 1' http://localhost:1313/     # добавить свой заголовок
curl --max-time 5 http://localhost:1313/     # не ждать вечно
```

Только код ответа — так обычно и делают в мониторинге:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:1313/
```

**Что потрогать на нашем сайте:**

```bash
curl -I http://localhost:1313/                  # 200, + наш X-Lesson
curl -I http://localhost:1313/css/style.css     # Content-Type: text/css, Cache-Control
curl -I http://localhost:1313/no-such-page/     # 404
curl -I http://localhost:1313/old-page          # 301 + Location: /about/
curl -sIL http://localhost:1313/old-page | grep -E 'HTTP/|Location'   # обе остановки
```

Когда HTTP-ответа нет вообще:

```bash
curl -s --max-time 3 http://localhost:9999/
```

- `Connection refused` — на порту никто не слушает (приложение не запущено / другой порт).
- `Timeout` — пакеты уходят в пустоту (файрвол, неверный адрес).

Разница принципиальная: refused — проблема в приложении, timeout — в сети.

## 6. HTML, CSS, JS — что за что отвечает

**HTML — структура.** Дерево вложенных коробок-тегов. `<div>` — безымянная коробка,
`<nav>`, `<main>`, `<section>`, `<footer>` — такие же коробки, но с понятным смыслом.

```html
<h1>Заголовок</h1>          <!-- ровно ОДИН на страницу -->
<p>Абзац</p>
<a href="/about/">Ссылка</a>
<img src="/images/logo.svg" alt="если картинка не загрузилась">
<ul><li>пункт</li></ul>
<button type="button">Кнопка</button>
```

Два атрибута-крючка:
- `class="..."` — за него цепляются CSS и JS. Классов на элементе может быть много.
- `id="..."` — уникальное имя, ровно один такой элемент на странице.

**CSS — оформление.** `селектор { свойство: значение; }`

```css
h1          { }   /* по тегу */
.neon-card  { }   /* по классу */
#mainNav    { }   /* по id */
.card p     { }   /* <p> внутри .card */
a:hover     { }   /* состояние: курсор наведён */
```

Кто побеждает при споре: id (100) > класс (10) > тег (1). При равном весе — тот,
кто **ниже** в файле; а файл, подключённый позже в `<head>`, перебивает подключённый раньше.
Поэтому наш `style.css` идёт после Bootstrap.

**JS — поведение.** Выполняется **в браузере**, не на сервере.

```js
document.getElementById('js-info')       // найти по id
document.querySelector('.copy-email')    // первый по CSS-селектору
document.querySelectorAll('.card')       // все
element.addEventListener('click', fn)    // реакция на событие
document.body.classList.toggle('theme-light')   // JS переключает класс, рисует CSS
```

Практический вывод: `/js/app.js` может открыть кто угодно — **токены и пароли
во фронтенд не кладут**. Ошибка в JS не роняет сервер: страница отдастся,
просто что-то не заработает. Смотреть — `F12` → **Console**.

**Подключение библиотек.** В `layouts/_partials/head.html`:

```html
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css"
      rel="stylesheet" integrity="sha384-..." crossorigin="anonymous">
<link rel="stylesheet" href="/css/style.css">
<script src="/js/app.js" defer></script>
```

- Bootstrap мы **не скачивали** — браузер идёт за ним на **чужой** сервер (CDN).
  Плюс: не занимает наш трафик, часто уже в кэше. Минус: упал CDN — сайт без стилей.
- `integrity` — хеш файла: подменили на CDN — браузер не применит.
- `defer` — «качай параллельно, выполни когда страница построена». Без него скрипт
  в `<head>` отработает раньше `<body>` и не найдёт ни одного элемента.

Открой `F12` → **Network** и перезагрузи страницу: увидишь, что одна страница —
это десяток запросов, часть из них на чужие домены.

## 7. Кэш браузера

Браузер не хочет качать одно и то же дважды и складывает файлы у себя.
Именно поэтому «я поправил CSS, а на сайте ничего не изменилось».

Управляет этим сервер, заголовком `Cache-Control` (у нас — в `hugo.toml`):

```bash
curl -I http://localhost:1313/css/style.css      # Cache-Control: public, max-age=60
curl -I http://localhost:1313/images/logo.svg    # Cache-Control: public, max-age=300
curl -I http://localhost:1313/                   # у HTML его нет вообще
```

`max-age=60` — «60 секунд можешь не спрашивать вообще». В эти 60 секунд браузер
берёт файл из памяти и **на сервер не ходит**: в Network увидишь `(from disk cache)`.

Когда срок вышел, браузер не качает заново вслепую, а **переспрашивает**:
шлёт `If-Modified-Since` с датой из `Last-Modified`. Проверь руками:

```bash
# 1. узнать дату файла
curl -I http://localhost:1313/css/style.css | grep -i last-modified

# 2. переспросить с этой датой
curl -s -o /dev/null -w "%{http_code} %{size_download} байт\n" \
     -H "If-Modified-Since: Wed, 05 Aug 2026 15:21:05 GMT" \
     http://localhost:1313/css/style.css
```

Ответ `304 0 байт` — «не менялось, бери своё». Тело не передавалось.
Вместо даты может использоваться `ETag` + `If-None-Match` — то же самое, но по хешу.

**Что с этим делать на практике:**

- `Ctrl+F5` / `Ctrl+Shift+R` — жёсткая перезагрузка, игнорировать кэш.
- `F12` → Network → галочка **Disable cache** — на всё время, пока открыт DevTools.
- Режим инкогнито — чистый кэш.
- В проде на статику ставят `max-age` в месяцы, а к именам файлов дописывают хеш
  (`style.a1b2c3.css`). Поменялся файл — поменялось имя — браузер качает как новый.
  Это называется **cache busting**.
- Ещё есть кэш CDN и прокси между тобой и сервером: `Cache-Control: public` разрешает
  им кэшировать тоже, `private` — только браузеру, `no-store` — никому.

Отдельно: `localStorage` (им пользуется наш переключатель темы) — **не кэш и не куки**.
Это хранилище в браузере, на сервер не отправляется никогда. `Ctrl+F5` его не чистит.

## 8. Практика

Сервер запущен, браузер и Git Bash открыты.

1. **Порт.** Подними сайт на `--port 8080`. Проверь `netstat`, зайди браузером,
   сделай `curl -I`. Потом запусти второй `hugo server` на том же порту — прочитай ошибку.
2. **Файлы.** Собери сайт командой `hugo`, найди в `public/` файл страницы `/about/`.
   Убедись, что это обычный HTML. Сравни его с `content/about.md`.
3. **Свой блок.** Добавь в `data/home.yaml` четвёртую карточку. Ничего в HTML не трогай.
4. **CSS.** Поменяй `--pink` в `static/css/style.css`. Убедись, что цвет поменялся везде.
5. **Кэш.** Поймай `(from disk cache)` во вкладке Network для `/images/logo.svg`.
   Потом добейся, чтобы он перезапросился.
6. **Сломай подключение.** Убери строку `<link rel="stylesheet" href="/css/style.css">`
   из `layouts/_partials/head.html` — посмотри, что осталось от страницы. Верни.
   Потом испорти путь на `/css/style2.css` — найди 404 во вкладке Network.
7. **JS.** Убери `defer` у `<script>` и перезагрузи. Текст-заглушка останется на месте,
   кнопка темы перестанет работать. Загляни в Console и объясни, почему.
8. **Коды.** Собери одной командой коды ответов для `/`, `/about/`, `/no-such-page/`, `/old-page`.
9. **Наружу.** Запусти с `--bind 0.0.0.0`, узнай свой IP (`ipconfig`) и открой сайт с телефона
   по той же wi-fi. Объясни, почему без этого ключа не работало.

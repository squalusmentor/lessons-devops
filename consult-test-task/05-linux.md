# 6. Linux: диски, ФС, процессы, службы

Команды выполняются на Linux-сервере или в WSL. В WSL нет LVM и своих физических дисков, поэтому `pvs` и `vgs` там покажут пустоту. Блок про LVM лучше показывать на виртуалке

---

## Диски

```bash
lsblk
```

Дерево блочных устройств: диски (`sda`, `nvme0n1`), разделы на них (`sda1`), LVM-тома и куда всё смонтировано

| Столбец | Что значит |
|---|---|
| `NAME` | имя устройства |
| `SIZE` | размер |
| `TYPE` | `disk` диск, `part` раздел, `lvm` логический том |
| `MOUNTPOINTS` | куда смонтировано |

```bash
sudo fdisk -l
```

Диски с таблицами разделов и точными размерами

## Файловые системы

ФС это способ разметить раздел под файлы и папки (`ext4`, `xfs`). Чтобы ФС была доступна, её монтируют в каталог

```bash
df -hT
```

Смонтированные ФС с типом, размером и занятым местом. `-h` переводит байты в ГБ, `-T` добавляет столбец с типом

```bash
lsblk -f
```

Какая ФС на каком разделе, с UUID

```bash
findmnt
```

Дерево точек монтирования

---

## Занятость диска, ФС, каталога

| Что | Команда | Что показывает |
|---|---|---|
| все ФС | `df -h` | размер, занято, свободно, процент по каждой ФС |
| одна ФС | `df -h /var` | ФС, на которой лежит `/var` |
| inode | `df -i` | количество файлов; кончаются раньше места, если файлов очень много мелких |
| каталог | `du -sh /var/log` | сколько весит каталог целиком |
| что внутри тяжёлое | `du -h --max-depth=1 /var \| sort -h` | вес подкаталогов, самые большие внизу |

`df` считает по ФС, `du` по файлам в каталоге. Цифры могут не совпадать: удалённый файл, который ещё держит открытым процесс, занимает место в `df`, но в `du` его уже нет

## LVM

LVM это прослойка между дисками и файловыми системами, позволяет объединять диски и менять размер разделов на ходу

| Уровень | Что это | Команда |
|---|---|---|
| PV, physical volume | диск или раздел, отданный под LVM | `sudo pvs` |
| VG, volume group | пул места из одного или нескольких PV | `sudo vgs` |
| LV, logical volume | «раздел», нарезанный из VG, на нём лежит ФС | `sudo lvs` |

```bash
sudo vgs
```

```
  VG        #PV #LV #SN Attr   VSize   VFree
  ubuntu-vg   1   1   0 wz--n- <48.00g 24.00g
```

Свободное место в группе показывает столбец `VFree`. Здесь 24 ГБ можно отдать существующему LV или создать новый. Если `VFree` равен `0`, места в группе нет, нужно добавлять диск

```bash
sudo vgdisplay
```

То же подробно, свободное место в строке `Free PE / Size`

## Каталоги и ссылки

```bash
mkdir -p /tmp/demo/logs
```

Создаёт каталог. `-p` создаёт все промежуточные и не ругается, если каталог уже есть

```bash
ls -la /tmp/demo
```

Содержимое каталога: `-l` подробно (права, владелец, размер, дата), `-a` вместе со скрытыми файлами

```bash
echo hello > /tmp/demo/logs/app.log
ln -s /tmp/demo/logs/app.log /tmp/demo/current.log
ls -l /tmp/demo
```

Символическая ссылка это отдельный файл, в котором записан путь к другому файлу. Программа, открывшая ссылку, работает с целевым файлом. Если цель удалить, ссылка останется и станет битой. В `ls -l` выглядит как `current.log -> /tmp/demo/logs/app.log`

| | Символическая `ln -s` | Жёсткая `ln` |
|---|---|---|
| что хранит | путь к файлу | ещё одно имя того же файла |
| если удалить оригинал | ссылка битая | файл доступен по второму имени |
| на каталог и другую ФС | можно | нельзя |

## Процессы

```bash
ps aux
```

Все процессы системы: владелец, PID, `%CPU`, `%MEM`, команда запуска

```bash
ps aux --sort=-%mem | head
```

Десять самых прожорливых по памяти

```bash
ps -ef --forest
```

Процессы деревом, видно кто кого запустил

```bash
pgrep -a nginx
```

## Загруженность ОС и утилизация ресурсов

```bash
uptime
```

```
 14:02:11 up 3 days,  2:15,  1 user,  load average: 0.52, 0.48, 0.40
```

Load average это среднее число процессов, которые работают или ждут CPU и диска, за 1, 5 и 15 минут. Сравнивай с числом ядер (`nproc`): load 2 на 4 ядрах нормально, load 8 на 4 ядрах значит задачи стоят в очереди

```bash
top
```

Всё сразу в реальном времени: load average, CPU, память, процессы. Внутри `M` сортирует по памяти, `P` по CPU, `1` показывает каждое ядро, `q` выход. `htop` то же самое, только удобнее, ставится отдельно

```bash
free -h
```

Память. Смотри на столбец `available`: сколько реально можно отдать процессам с учётом кэша

```bash
vmstat 1 5
```

Пять замеров раз в секунду: очередь процессов (`r`), своп (`si`/`so`), ожидание диска (`wa`)

```bash
iostat -x 1
```

Нагрузка на каждый диск, `%util` близко к 100 значит диск не успевает. Ставится пакетом `sysstat`

## Службы

Служба это фоновая программа, которой управляет systemd: запускает при загрузке, перезапускает при падении

```bash
systemctl status ssh
```

Состояние службы: `active (running)` или `failed`, PID, память, последние строки лога. На RHEL-системах служба называется `sshd`

| Команда | Что делает |
|---|---|
| `systemctl is-active ssh` | одно слово: `active` или нет, удобно в скриптах |
| `systemctl list-units --type=service --state=failed` | все упавшие службы |
| `sudo systemctl restart ssh` | перезапустить |
| `sudo systemctl enable ssh` | запускать при загрузке |

В старых WSL systemd выключен, `systemctl` пишет `System has not been booted with systemd`. Включается в `/etc/wsl.conf` блоком `[boot]` со строкой `systemd=true`, потом `wsl --shutdown` из PowerShell

## Логи служб

```bash
journalctl -u ssh
```

Все логи службы из журнала systemd

| Флаг | Что делает |
|---|---|
| `-n 50` | последние 50 строк |
| `-f` | следить в реальном времени |
| `--since "1 hour ago"` | за последний час |
| `-p err` | только ошибки |
| `-b` | с последней загрузки системы |

Часть программ пишет логи в свои файлы мимо журнала. Их ищут в `/var/log`, например `/var/log/nginx/error.log`, и смотрят через `tail -f`
